# Техническое задание: Foundly

Сервис поиска потерянных и найденных вещей в университете.

## 1. Цель проекта

Создать веб-сайт, где студенты и сотрудники университета публикуют объявления о потерянных и найденных вещах, быстро находят нужное по фильтрам и связываются с автором объявления. Все пользователи видят единую общую ленту.

Проект учебный и портфолио-ориентированный: демонстрирует fullstack-разработку на Next.js с облачной базой данных, авторизацией и хранилищем файлов.

## 2. Проблема

Потерянные вещи (ключи, наушники, студенческий, зарядки, одежда) ищут через разрозненные чаты и объявления на стенах. Информация теряется, нет единого места и статуса поиска.

## 3. Целевая аудитория

- Студенты университета (основная группа)
- Преподаватели и сотрудники
- Администрация и охрана (находят вещи в корпусах)

## 4. Функциональные требования

### 4.1. Авторизация

- Регистрация и вход по email и паролю (Supabase Auth)
- Выход из аккаунта
- Просмотр ленты доступен без входа
- Создание, изменение и удаление объявлений доступно только авторизованным пользователям

### 4.2. Лента объявлений

- Список карточек: фото, название, категория, место, дата, статус
- Карточки адаптивны: сетка на компьютере, колонка на телефоне
- Сортировка: сначала новые
- Данные загружаются из базы данных и видны всем пользователям

### 4.3. Создание объявления

Форма с полями:

- Тип: «Потерял» или «Нашёл» (обязательно)
- Название вещи (обязательно)
- Категория (обязательно)
- Описание
- Место (корпус или аудитория) (обязательно)
- Дата (по умолчанию сегодня)
- Фото (загрузка файла в хранилище)
- Контакт: Telegram-ник (обязательно)

Валидация: пустые обязательные поля не пропускаются, показывается сообщение об ошибке. Ограничение на размер фото (до 5 МБ) и формат (jpg, png, webp).

### 4.4. Фильтры и поиск

- Поиск по названию
- Фильтр по категории
- Фильтр по типу («Потерял» / «Нашёл»)
- Фильтр по статусу
- Фильтр по дате (за сегодня, за неделю, за всё время)
- Кнопка «Сбросить фильтры»

### 4.5. Статусы

Каждое объявление имеет один из статусов:

- **Ищется** (по умолчанию)
- **Найдено**
- **Возвращено**

Менять статус может только автор объявления. Статус отображается цветным бейджем на карточке.

### 4.6. Страница объявления

- Полная информация и большое фото
- Кнопка «Связаться в Telegram» (ссылка `https://t.me/<ник>`)
- Для автора: кнопки смены статуса и удаления объявления

### 4.7. Мои объявления

- Страница со списком объявлений текущего пользователя

## 5. Категории вещей

Документы и карты, ключи, электроника, одежда, сумки и рюкзаки, книги и тетради, другое.

## 6. Структура страниц

| Путь | Назначение |
|---|---|
| `/` | Главная: лента объявлений, поиск, фильтры |
| `/add` | Форма нового объявления (только для вошедших) |
| `/item/[id]` | Страница отдельного объявления |
| `/my` | Мои объявления |
| `/login`, `/register` | Вход и регистрация |
| `/about` | О проекте и как это работает |

## 7. Модель данных

Таблица `items` (PostgreSQL, Supabase):

```
id          — uuid, первичный ключ
user_id     — uuid, ссылка на пользователя (auth.users)
type        — "lost" | "found"
title       — название
category    — категория
description — описание
place       — место
date        — дата
image_url   — ссылка на фото в Supabase Storage
telegram    — ник автора
status      — "searching" | "found" | "returned"
created_at  — дата создания
```

Хранилище фото: бакет `item-images` в Supabase Storage.

## 8. Безопасность

- Row Level Security (RLS) включена на таблице `items`:
  - читать объявления может любой посетитель
  - создавать может только авторизованный пользователь, `user_id` равен его id
  - изменять и удалять может только автор (`user_id = auth.uid()`)
- Ключи доступа хранятся в `.env.local`, файл не попадает в Git
- Переменные окружения для деплоя задаются в настройках Vercel
- Ввод пользователя проверяется на клиенте и в базе (ограничения полей)

## 9. Технические требования

- Next.js (App Router), TypeScript
- Tailwind CSS
- Бэкенд: Supabase (PostgreSQL, Auth, Storage)
- Клиентская библиотека: `@supabase/supabase-js`
- Версионирование: Git, репозиторий на GitHub
- Деплой: Vercel
- Поддержка браузеров: актуальные Chrome, Firefox, Safari, Edge

## 10. Требования к дизайну

- Адаптивность: корректное отображение на экранах от 360 px
- Чёткая цветовая схема статусов (например: ищется — жёлтый, найдено — зелёный, возвращено — серый)
- Читаемые шрифты, достаточные отступы, понятные кнопки
- Состояния: пустая лента («Ничего не найдено»), загрузка, ошибка формы и сети

## 11. Вне рамок первой версии

- Внутренний чат и система откликов (вместо этого связь через Telegram)
- Карта корпусов
- Push- и email-уведомления
- Панель администратора и модерация
- Вход через Google и университетскую почту

## 12. Монетизация (концепция)

Партнёрство с университетами и организациями: брендированная версия сервиса для кампуса, статистика возвратов для администрации. В рамках учебной версии не реализуется.

## 13. Этапы выполнения

1. **Подготовка:** репозиторий, Next.js, README, структура папок
2. **Supabase:** создание проекта, таблица `items`, бакет для фото, политики RLS, ключи в `.env.local`
3. **Авторизация:** страницы входа и регистрации, выход
4. **Лента:** загрузка объявлений из базы, карточки, страница `/`
5. **Форма:** страница `/add`, валидация, загрузка фото, сохранение
6. **Фильтры и поиск**
7. **Страница объявления:** `/item/[id]`, статусы, удаление, Telegram, страница `/my`
8. **Дизайн и адаптивность**
9. **Тестирование и деплой на Vercel**

## 14. Критерии готовности

- Пользователь может зарегистрироваться, войти и выйти
- Объявление можно создать с фото, и его видят все посетители сайта
- Только автор может менять статус и удалять своё объявление (проверено и через интерфейс, и политиками RLS)
- Фильтры и поиск работают вместе
- Сайт нормально выглядит на телефоне и компьютере
- Ключи не попали в репозиторий
- Проект задеплоен и доступен по ссылке
- В README описаны запуск, переменные окружения и структура проекта
