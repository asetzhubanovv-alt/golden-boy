# Техническое задание: Foundly

Сервис поиска потерянных и найденных вещей в университете.

## 1. Цель проекта

Создать веб-сайт, где студенты и сотрудники университета публикуют объявления о потерянных и найденных вещах, быстро находят нужное по фильтрам и связываются с автором объявления.

Проект учебный и портфолио-ориентированный: демонстрирует работу с Next.js, состоянием, формами, фильтрацией и адаптивной вёрсткой.

## 2. Проблема

Потерянные вещи (ключи, наушники, студенческий, зарядки, одежда) ищут через разрозненные чаты и объявления на стенах. Информация теряется, нет единого места и статуса поиска.

## 3. Целевая аудитория

- Студенты университета (основная группа)
- Преподаватели и сотрудники
- Администрация и охрана (находят вещи в корпусах)

## 4. Функциональные требования

### 4.1. Лента объявлений

- Список карточек: фото, название, категория, место, дата, статус
- Карточки адаптивны: сетка на компьютере, колонка на телефоне
- Сортировка: сначала новые

### 4.2. Создание объявления

Форма с полями:

- Тип: «Потерял» или «Нашёл» (обязательно)
- Название вещи (обязательно)
- Категория (обязательно)
- Описание
- Место (корпус или аудитория) (обязательно)
- Дата (по умолчанию сегодня)
- Фото (ссылка или загрузка файла)
- Контакт: Telegram-ник без символа `@` (обязательно)

Валидация: пустые обязательные поля не пропускаются, показывается сообщение об ошибке.

### 4.3. Фильтры и поиск

- Поиск по названию
- Фильтр по категории
- Фильтр по типу («Потерял» / «Нашёл»)
- Фильтр по статусу
- Фильтр по дате (за сегодня, за неделю, за всё время)
- Кнопка «Сбросить фильтры»

### 4.4. Статусы

Каждое объявление имеет один из статусов:

- **Ищется** (по умолчанию)
- **Найдено**
- **Возвращено**

Автор может менять статус. Статус отображается цветным бейджем на карточке.

### 4.5. Страница объявления

- Полная информация и большое фото
- Кнопка «Связаться в Telegram» (ссылка `https://t.me/<ник>`)
- Кнопка смены статуса
- Кнопка удаления объявления

### 4.6. Хранение данных

- Данные хранятся в `localStorage` браузера
- Данные не пропадают после перезагрузки страницы
- При первом запуске загружаются 6–8 демонстрационных объявлений

## 5. Категории вещей

Документы и карты, ключи, электроника, одежда, сумки и рюкзаки, книги и тетради, другое.

## 6. Структура страниц

| Путь | Назначение |
|---|---|
| `/` | Главная: лента объявлений, поиск, фильтры |
| `/add` | Форма нового объявления |
| `/item/[id]` | Страница отдельного объявления |
| `/about` | О проекте и как это работает |

## 7. Модель данных

Объявление:

```
id          — уникальный идентификатор
type        — "lost" | "found"
title       — название
category    — категория
description — описание
place       — место
date        — дата
image       — ссылка или base64
telegram    — ник автора без символа @
status      — "searching" | "found" | "returned"
createdAt   — дата создания
```

## 8. Технические требования

- Next.js (App Router), TypeScript
- Tailwind CSS
- Хранение: localStorage
- Версионирование: Git, репозиторий на GitHub
- Деплой: Vercel
- Поддержка браузеров: актуальные Chrome, Firefox, Safari, Edge

## 9. Требования к дизайну

- Адаптивность: корректное отображение на экранах от 360 px
- Чёткая цветовая схема статусов (например: ищется — жёлтый, найдено — зелёный, возвращено — серый)
- Читаемые шрифты, достаточные отступы, понятные кнопки
- Состояния: пустая лента («Ничего не найдено»), загрузка, ошибка формы

## 10. Вне рамок первой версии

Не входит в MVP, возможно в будущих версиях:

- Внутренний чат и система откликов
- Регистрация и авторизация
- Серверная база данных и хранилище фото (например, Supabase)
- Карта корпусов
- Уведомления

## 11. Монетизация (концепция)

Партнёрство с университетами и организациями: брендированная версия сервиса для кампуса, статистика возвратов для администрации. В рамках учебной версии не реализуется.

## 12. Этапы выполнения

1. **Подготовка:** репозиторий, Next.js, README, структура папок
2. **Данные:** тип объявления, демонстрационные данные, чтение и запись в localStorage
3. **Лента:** карточки, страница `/`
4. **Форма:** страница `/add`, валидация, сохранение
5. **Фильтры и поиск**
6. **Страница объявления:** `/item/[id]`, статусы, удаление, Telegram
7. **Дизайн и адаптивность**
8. **Тестирование и деплой на Vercel**

## 13. Критерии готовности

- Объявление можно создать, увидеть в ленте, открыть, изменить статус и удалить
- Фильтры и поиск работают вместе
- После перезагрузки данные сохраняются
- Сайт нормально выглядит на телефоне и компьютере
- Проект задеплоен и доступен по ссылке
- В README описаны запуск и структура проекта
